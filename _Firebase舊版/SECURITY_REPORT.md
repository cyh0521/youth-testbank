# 幼獅題庫系統 — 帳號安全性審查報告

## 📋 問題修正摘要

### 1. ✅ 登入身份驗證強化
**問題**：選擇「教師/管理員」或「學生」後，無論選哪個都能登入成功。
**修正**：
- 現在會嚴格驗證帳號角色是否符合選擇的身份
- 身份不符會立即登出並顯示錯誤訊息，要求選擇正確身份
- 程式碼位置：`index.html` 的 `doLogin()` 函數

### 2. ✅ 登入頁面說明文字
**問題**：說明文字不區分教師與學生。
**修正**：
- **教師/管理員**：顯示「教師帳號請聯繫幼獅業務同仁協助申請。」
- **學生**：顯示「學生還沒有帳號？點此加入」
- 切換身份時，說明文字會自動切換

### 3. ✅ Session 持久性（關閉瀏覽器需重新登入）
**問題**：重開瀏覽器後仍自動登入，之前的登入沒被強制離線。
**修正**：
- 使用 Firebase `browserSessionPersistence`
- 關閉瀏覽器分頁後，登入狀態自動失效
- 程式碼位置：`index.html`、`js/firebase.js`

### 4. ✅ Firestore 安全規則強化
**修正內容**：
- **試卷 (exams)**：教師只能讀取/修改自己建立的試卷
- **成績 (results)**：記錄考試所屬班級和出題教師
- **班級 (classes)**：教師只能管理自己建立的班級
- **題庫 (questions)**：只有管理員可以新增/修改/刪除

### 5. ✅ 教師資料隔離
**修正**：
- **試卷管理**：教師只能看到自己建立的試卷（管理員可看全部）
- **成績查詢**：教師只能看到自己班級學生的成績
- 程式碼位置：`exams.html`、`results.html`

### 6. ✅ 學生考試權限
**已確認運作正常**：
- 學生只能看到已加入班級的開放試卷
- 未加入任何班級的學生無法參加考試
- 程式碼位置：`take.html` 的 `loadAvailableExams()`

## ⚠️ 安全建議（尚未實作）

### 1. 管理員驗證碼安全性
**現況**：`admin2024` 硬編碼在前端程式碼中
**風險**：任何人查看原始碼即可取得
**建議**：
- 移除前端初始化管理員功能
- 改由 Firebase Admin SDK 或 Cloud Functions 處理
- 或將驗證碼存於 Firestore 並定期更換

### 2. API Key 保護
**現況**：Firebase API Key 暴露在前端
**說明**：Firebase API Key 暴露是正常設計，安全性由 Firestore 規則保護
**建議**：
- 在 Firebase Console 設定 API 限制（限定網域）
- 啟用 App Check 增加額外防護

### 3. 密碼強度要求
**現況**：只要求至少 6 字元
**建議**：
- 要求包含大小寫字母和數字
- 禁止常見密碼（如 123456、password）

### 4. 登入嘗試限制
**現況**：依賴 Firebase 內建的 `auth/too-many-requests`
**建議**：
- 增加前端的嘗試次數限制
- 顯示驗證碼（CAPTCHA）防止暴力攻擊

### 5. 審計日誌
**現況**：無
**建議**：
- 記錄所有登入/登出事件
- 記錄敏感操作（刪除帳號、修改權限等）
